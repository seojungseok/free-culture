# 방문자 집계 복구 (2026-11-15)

## 확인한 원인과 이전 기록

운영 `/api/visitors`가 약 5초 뒤 503을 반환했다. 기존 Abacus의 `get/weekendpick-kr/total`, `d20261115` 조회에서도 시간 초과와 500이 발생했다. 같은 제공자의 공식 문서 주소 `abacus.jsn.cam`에서는 개별 조회가 간헐적으로 성공했다. 확인된 값은 누적 55,908, 2026-11-15 일일 315이며, 두 값은 각각 별도 HTTP 200 응답으로 확인했다. 이 값을 공개 기준 파일에 보존했다. 기존 키에 생성·증가·설정·초기화·삭제 요청을 보내지 않았다.

이전 브라우저 코드는 서버 응답 전에 완료 표시를 저장했다. 증가가 실패한 방문도 해당 세션에서는 다시 시도되지 않았다. 외부 카운터 자체의 장애와 이 누락 경로를 함께 수정했다.

## 저장과 중복 방지

- NAS의 `free-culture-nas_visitor_counter` named volume을 `/app/visitor-counter`에 연결한다. Dockerfile은 UID/GID 10001의 전용 쓰기 디렉터리를 준비한다. 재배포는 기존 볼륨을 재사용한다. `docker compose down -v`, volume 삭제/초기화를 운영 절차에 추가하지 않는다.
- 기존 확인 수는 `baseline.json`을 처음 만들 때만 가져온다. 이후 기준 파일을 배포해도 실제 저장 기록을 덮어쓰지 않는다. 저장 경로 누락이나 손상 시 가짜 0으로 초기화하지 않는다.
- 한국시간 날짜별 append-only 파일에 세션 토큰의 일일 SHA-256 해시만 기록한다. 한 번의 append와 fsync, Linux 디렉터리 fsync 후 응답한다. 재시작 시 파일을 다시 읽으며 중복 해시는 한 번만 계산한다. 독립 프로세스가 같은 토큰을 동시에 쓰더라도 방문 수는 한 번만 증가한다.
- 요청 원문·IP·User-Agent·검색어·방문 경로·원래 세션 토큰은 방문자 파일에 저장하지 않는다. 개인정보처리방침을 실제 동작에 맞게 갱신했다.
- 클라이언트는 서버가 저장을 확인한 뒤에만 기존 `vc_YYYYMMDD` 완료 표시를 남긴다. 응답 유실 시 같은 임의 토큰으로 재시도한다. 이미 완료된 이전 세션의 표시는 존중한다. 브라우저 저장소가 차단되거나 로컬 미리보기이면 조회만 한다.
- 활성 화면에서 60초 간격과 다시 화면으로 돌아올 때 수를 갱신한다. 한국시간 자정에는 같은 세션도 새 날짜에 한 번 집계한다. 요청/타이머/이벤트는 화면 이탈 시 정리한다.

## 이전 서버의 늦게 반영된 수 보존

새 서버 시작 1분 뒤부터 요청 응답과 분리해 원래 `total`, 이전 당일 키를 최대 5분 간격으로 읽는다. 개별 최대값만 보존하고 신규 로컬 방문 수를 별도로 더하므로 늦은 이전 기록이 로컬 기록을 덮어쓰지 않는다. 둘 다 성공한 뒤 이 복구 조회는 영구 중단한다. 응답 지연·실패는 새 방문 저장이나 표시를 막지 않는다.

장애 때 원래 서버에도 저장되지 않은 방문은 과거 기록을 만들어 채우지 않는다. 표시 수는 원래부터 브라우저 세션별 일일 수이며 GA4의 고유 사용자 수와 동일한 지표가 아니다.

## 검증

23개 모의/로컬 검사 통과: 기존 일자·누적값, 응답 유실 재시도, Strict Mode, 저장소 제한, 한국시간 자정, 재시작, 여러 프로세스 동시 기록, 중복 행, 중간에 끊긴 파일, 외부 서버 장애, 부분 복구, 제휴 측정 회귀. 타입 검사와 수정 TSX lint 오류 0개.

운영 배포의 smoke 검사에 읽기 전용 `/api/visitors`를 추가했다. `X-Visitor-Store: persistent-v1`, 정상 오늘·누적 정수를 확인한다. 공개 릴리스 SHA, NAS 종료 상태, API 응답과 화면 증거는 `.cache/visitor-counter-*`에 저장한다.
