# 네이버 검색·공유 정보 점검 (2026-11-15)

## 적용

- 기존 공개 글의 제목/H1/canonical/주소와 상품 제휴 추적 URL을 유지한다.
- 67개 페이지 템플릿에서 기존 검색 설명과 OG/Twitter 설명을 맞추고, 빠진 공유 주소와 브랜드 대표 이미지 기본값을 채운다. 실제 기관 사진과 기존 공유 제목·이미지는 보존한다.
- 홈 일반 카드에 기존 콘텐츠 제목을 이미지 대체 설명으로 사용한다. 원본 이미지 설명이 있으면 우선한다.
- `/rss.xml`: 현재 공개·색인 가능한 체험·교육 중 60개를 세 분류에서 섞어 제공한다. 내부 상세 URL을 고유 주소로 사용하며, 실제 상세 본문·프로그램·일정·대상·비용·주소·문의처·출처와 공식 신청 안내를 담는다. 수집 확인일을 발행일로 바꾸지 않는다.
- RSS는 저장된 공공자료만 읽고 한 시간 캐시한다. 방문자 렌더링에서 외부 API를 새로 호출하지 않는다.
- 삭제된 장소의 React 오류 화면이 HTTP 200으로 스트리밍되는 문제는 middleware에서 404/noindex로 먼저 처리한다. 식당·캠핑으로 이관된 이전 주소도 스트리밍 전에 기존 목적지로 HTTP 308을 반환한다. `next.config.mjs`를 읽을 때 최신 장소·식당·캠핑 별칭의 ID와 이동 경로만 담은 색인을 생성한다. 정상 장소 10,704개와 이전 주소의 목적지는 유지한다. 색인이 불완전하면 빌드를 실패시킨다.
- 검색 결과·필터·보관함·내용이 부족한 자료의 기존 noindex를 유지한다. 네이버에서 중복으로 보고된 검색 주소 24개는 현재 noindex 상태였으므로 검색 노출 대상으로 바꾸지 않는다.
- RSS와 없는 장소의 404를 NAS 배포 검사에 포함한다. 기존 방문자 영구 저장 검사는 유지한다.

## 검증 기준

네이버 공식 Yeti User-Agent로 공개 페이지의 head 메타데이터·H1·구조화 데이터·canonical·공유 이미지를 읽는다. 제목·canonical·robots는 배포 전과 비교한다. 사이트맵의 중복·다른 도메인·사라진 주소 포함 여부를 확인한다. RSS XML은 파서로 검사하고 본문, 출처와 내부 permalink를 대조한다.

네이버 진단은 과거 수집 결과이므로 코드 배포 직후 숫자가 사라진다고 보고하지 않는다. 직접 HTTP 확인과 서치어드바이저 제출·실시간 검사 결과를 구분한다. 검색 순위나 방문자 증가 시점은 보장하지 않는다.
