# 홈페이지 초기 로딩 및 겨울 음료 기획전

## 확인한 원인과 수정

- 공개 홈페이지 모바일 390×844의 격리된 새 브라우저 방문에서 요청 63개를 관측했다. 클릭하지 않은 다른 경로의 RSC 미리 읽기 11개와 그에 따른 페이지 스크립트가 있었다. 홈과 공통 헤더의 링크는 화면에 보인다는 이유만으로 미리 읽지 않고, 마우스로 가리키거나 키보드 초점을 옮긴 링크만 준비한다. 클라이언트 이동은 유지한다.
- 기존 `/shopping/coffee`의 첫 HTML에는 상품 카드가 없고 `상품을 불러오고 있어요`만 있었다. 기획전은 서버의 로컬 공개 상품 캐시로 첫 HTML부터 렌더한다. 방문자 요청에서 판매처 API를 호출하지 않는다. 기존 root layout보다 새로운 페이지 캐시를 우선하며, 더 최신의 클라이언트 갱신이 오면 이를 반영한다.
- 홈 페이지 JS에 필요 없는 전체 상품 스냅샷·제휴 링크·선택 안내가 포함된 것을 확인했다. 서버에서 배너용 필드만 전달하도록 분리하여 홈 페이지 청크를 68,969 → 55,775 bytes로 줄였다(압축 전 해당 청크, 약 19%). 전체 JS나 실제 화면 속도 19% 개선을 의미하지 않는다.
- 외부 글꼴은 다운로드가 끝나기 전에 hydration effect가 `media=all`로 바꾸지 않도록 했다. 이미 로드된 캐시는 `.sheet`로 처리하고, 미완료 CSS는 load 이벤트까지 비차단 상태를 유지한다.

초기 HTTP 저부하 표본에서 홈페이지 응답은 TTFB 218~463ms, 상품 공개 캐시 API는 87~98ms였다. 이는 화면 표시·클릭 반응·NAS 전체 부하의 측정값이 아니다. Lighthouse 공개 API는 공유 일일 한도 429로 사용할 수 없었고 LCP·INP·CLS 점수는 측정하지 않았다.

## 따뜻한 한 잔

- 커피 한 종류였던 배너를 커피·율무차·유자차·계피생강차의 4종 음료 연출 사진으로 교체했다. 한글 문구는 비트맵에 직접 들어 있다. 원본 생성 및 프롬프트는 `winter-drinks-ad-20261113.json`에 기록했다.
- `/shopping/winter-drinks`로 연결하고 기존 `/shopping/coffee`는 301로 새 모음에 연결한다. 사이트맵과 canonical도 새 모음과 일치한다.
- 새 3종은 토스 best-category 및 detail 응답의 상품명·선택 옵션·사진·가격·재고와 원본 제휴 링크를 대조했다. 확인 시각은 상품 스냅샷에 기록했다. 3만 원 이상 상품은 계속 제외한다. 배너 사진은 일반 음료의 AI 연출이고 상품 카드는 판매처 사진이다.
- 수집기 버전 2부터 새 음료의 누락도 확정된 수집 결과로 존중한다. 이전 수집기와의 전환 중 스냅샷은 원래 확인 시각 기준 6시간 안에서만 사용하며 확인 시각을 연장하지 않는다. 기존 모음의 버전 1 판정도 보존한다.
- PC 5.5:1(1760×320, 80,108 bytes), 모바일 3:1(960×320, 45,964 bytes). 5개 배너 및 5초 회전을 유지한다.

## 검증

- 관련 자동 검증 38개 통과. 첫 서버 HTML에 음료 카드 4개가 있으며 로딩 문구가 없음을 확인했다. 더 최신의 빈 수집 결과가 오면 카드가 제거되고, 서버 캐시가 잠시 비었어도 클라이언트 갱신으로 복구되는 검증도 통과했다.
- 최종 생산 빌드 성공, 1416개 정적 경로 생성. 기존의 다른 컴포넌트 이미지·hook 경고는 별도로 남아 있다.
- 로컬 생산 서버에서 신규 모음 200 및 첫 HTML 상품 4개, 김장 모음 200 및 상품 4개, 구 커피 URL 301을 확인했다.
- 344px 커버 화면, 768px 펼친 화면, 1440px PC에서 넘침이 없고 상품 사진·구매 링크와 배너 문구가 표시됨을 확인했다. 운영 반영 후 동일한 공개 브라우저 조건의 요청 수와 실제 구매 경로를 추가 확인한다.

적용한 설치된 전문 스킬: web-perf, performance-profiler, Vercel React Best Practices. 기준 자료: [Next.js Prefetching](https://nextjs.org/docs/app/guides/prefetching), [Server and Client Components](https://nextjs.org/docs/app/getting-started/server-and-client-components), [Vercel Agent Skills](https://github.com/vercel-labs/agent-skills).

## 운영 확인에서 발견한 추가 원인

첫 배포 `7134d56`는 NAS 23:15:01~23:19:12에 정상(0)으로 종료했다. 동일한 390×844 격리 브라우저 시나리오에서 요청 63→44개, 클릭하지 않은 다른 페이지의 미리 읽기 10→0개를 관측했다. 첫 배포 이후에도 남아 있던 자기 페이지 RSC 요청 1개와 HEAD 확인 요청 2개는 이미 11월 8일 종료된 행사 때문에 발생했다. `expiresAt`이 있는 기록이 남아 있다는 이유만으로 서버 캐시를 계속 막고, 새 방문마다 만료 확인과 `router.refresh()`를 실행하는 구조였다.

서버에서는 아직 앞으로 남은 마감만 실시간 렌더와 클라이언트 타이머에 전달한다. 모든 마감이 지난 뒤에는 만료 기록이 제거된 결과를 기존 ISR 정책으로 다시 캐시한다. 원본 행사 데이터와 구 URL/이미지의 410 처리는 유지한다. 미래 마감이 있는 동안에는 기존대로 no-store로 사전 만료 응답의 캐시를 막고, 이미 열린 탭도 마감에 맞춰 갱신한다.

추가 변경 검증 46개 및 생산 빌드(1416개 정적 경로)가 통과했다. 로컬 생산 서버의 홈페이지가 `s-maxage=60`, `x-nextjs-cache: HIT`를 반환하며, 기존 만료 상세/별칭/이미지는 모두 410·no-store·noindex를 유지하고, 음료 페이지는 첫 HTML에 4개 카드를 표시함을 확인했다. 공개 Lighthouse 및 현장 Core Web Vitals 수치는 이번 측정에 포함하지 않는다.
