## 검사 범위와 적용 역할

`agency-agents`의 `marketing/marketing-seo-specialist.md`, `testing/testing-api-tester.md`를 읽고 검색 의도·canonical·사이트맵·응답 계약·실패 시 보존을 점검했다. **초기 코드 감사 당시** Google Search Console 접근 자료가 없어 문서의 **Pre-GSC sitemap + query-intent fallback**을 적용했다. 이후 담당자가 진행하는 인증된 Search Console 화면 검토는 별도이며, 이 공개 문서에는 비공개 통계를 넣지 않는다. 클릭·노출·검색순위·검색량·색인율·Core Web Vitals 수치는 추정하지 않았다. 외부 공공 API는 총 6회 읽기 표본만 호출했고 부하시험·한도 소진시험은 실행하지 않았다. 단일 응답시간은 p95나 서비스 SLA 증거가 아니다.

이 문서는 개편 전 공개 사이트 상태와 이번 변경의 로컬 검사 결과다. 겨울여행 20개 본문·배너의 최종 배포 검증은 별도 출시 검증에 기록한다.

- `/api/site-status`: HTTP 200, `ready=true`, commit `217d617905ec4583d9b74600c6e12fd77450827d`.
- 홈, `/events`, `/festivals`, `/places`, `/food`, `/camping`, `/pet-travel`, `/winter-travel`: 모두 HTTP 200. 각 HTML의 H1 1개, 해당 페이지 canonical, index 허용 확인.

## 수정 사항

1. **오래된 운영정보가 영구 고정되는 문제**: 음식점/관광지 영업·이용시간과 상세 항목을 미수집 또는 30일 지난 순으로 다시 확인한다. 주간 610회 예산은 그대로이며 배분은 338/169/103회다. 호출량이 제한되어 전체 레코드를 30일 내 모두 갱신한다는 보장은 하지 않는다.
2. **빈 응답 보호와 재시도 순환**: 공식 응답이 비면 이전 유효 내용을 보존한다. 별도 `successfulChecks`는 재조회 시도 관리에만 사용하고 기존 사실의 `checkedAt`을 새 날짜로 위장하지 않는다.
3. **음식점 목록 갱신**: 기존 ID도 주소·사진·전화·소스 변경시각을 재확인한다. `RESTO_MAX`는 신규 추가 수에만 적용하며 기존 URL을 제거하지 않는다. 페이지당 1,000건 조회로 같은 100회 예산 안에서 목록을 순회한다. 확인 실패 시 이전 파일을 보존한다.
4. **잘못된 캠핑 사진**: 실제 캐시에 `.pptx` 파일 한 개가 이미지로 남아 있었다. 화면에서 이미지 파일형식만 허용하고 수집기는 갤러리의 유효 사진을 선택한다. HTTP/인증/한도 오류를 공통 client에서 검증하고 재시도도 요청 예산에 포함한다.
5. **반려동물 최신시각 위장 방지**: 모든 목록 조회가 실패하면 파일과 마지막 확인시각을 보존하고 실패를 반환한다. 부분 성공은 `incompleteRefresh`와 성공 페이지/실패 횟수를 남긴다. 전용 반려동물 키만 있는 경우도 올바르게 인식한다.

배너·제휴 추적 정보와 다른 카테고리 글/URL은 삭제하지 않았다. 쿠팡 API를 호출하지 않았다.

## 검색 최적화 기준 출처

- [Google 사이트맵 lastmod 지침](https://developers.google.com/search/blog/2023/06/sitemaps-lastmod-ping): 실제 주요 내용 변경시각을 사용하며, 단순 빌드/확인 날짜를 모든 URL에 찍지 않는다. priority/changefreq 수정으로 노출 상승을 주장하지 않는다.
- [Google Article 구조화 데이터](https://developers.google.com/search/docs/appearance/structured-data/article): 실제 본문과 맞는 제목·관련 이미지·발행/수정 시각을 제공한다. 코드 적용과 검색 결과 노출 여부는 별개다.
