# 홈페이지 제휴 배치와 오프라인 측정 — 2026-11-06

실제 NAS 이벤트 로그, GA4 수신 통계, 구매·수수료·취소·정산 보고서는 조회하지 않았다. 아래 결과는 소스 코드 조사, 공식 문서 확인, 합성 입력을 사용한 로컬 테스트다. 매출 증가나 구매 전환 개선을 확인한 보고서가 아니다.

## 적용 역할과 근거

Agency의 `paid-media/paid-media-tracking-specialist.md`는 발신·수신 계약과 지표 정의 점검에, `marketing/marketing-growth-hacker.md`는 방문 목적과 광고 가설의 분리·검증에 적용했다. 역할 문서의 예시 성장률이나 정확도 목표를 이 사이트의 실제 성과로 사용하지 않았다.

1. 여행 탐색을 먼저 보여주고 관련 정보 사이에 광고를 둔다. Google의 광고 배치 안내는 방문자가 원하는 콘텐츠를 쉽게 찾게 하고 광고가 탐색 메뉴로 오해되지 않도록 권한다. 이 사이트의 토스 제휴에는 **UX 참고 원칙**으로 적용하며, AdSense 사용이나 그 프로그램 규정의 직접 적용을 뜻하지 않는다. [Google AdSense 광고 배치 안내](https://support.google.com/adsense/answer/1282097?hl=en)
2. 상품 설명을 반복하는 것보다 실제 여행 코스, 사용 조건, 선택 기준 등 독자에게 필요한 정보를 유지한다. Google Search는 판매자의 설명을 복제하고 추가 가치를 주지 않는 제휴 콘텐츠와 유용한 탐색·비교 정보를 제공하는 콘텐츠를 구별한다. 본문보다 광고가 먼저 길게 이어지지 않게 하자는 제안은 이 원칙을 현재 화면에 적용한 판단이다. [Google Search thin affiliation](https://developers.google.com/search/docs/essentials/spam-policies#thin-affiliation)
3. 이미지와 광고 영역의 비율·높이를 먼저 확보한다. 로딩 뒤 삽입되는 영역이 읽던 내용을 밀어내는지 첫 로드와 스크롤 모두 확인한다. 이 보고서는 운영 CLS 측정값을 수집하지 않았다. [web.dev CLS 개선 안내](https://web.dev/articles/optimize-cls)

## 실제로 기록할 수 있는 것

- 서버는 `at`, `event`, `provider`, `placement`, `page`, 선택적 `productId`만 저장한다. 이벤트는 노출·외부 클릭·저장 동작이다. 조회용 GET 통계 API나 관리 화면은 확인되지 않았다.
- 배너 노출 기준은 관찰 면적 35%, 카드 기준은 50%다. 지속 시간 조건이 없으므로 표준적인 광고 가시 노출 수로 부르지 않는다. 서로 다른 기준의 영역을 단순 비교하지 않는다.
- `affiliate_save`는 저장과 해제 모두 포함한다. 집계의 `saveActions`는 최종 저장 상품 수가 아니다.
- 사용자·세션·이벤트 고유 ID가 없다. 반복 이벤트를 임의 제거하거나 사용자 수, 사용자 전환율을 추정하지 않는다. 자체 로그와 GA4는 별도 경로이므로 합산하지 않는다.
- 주문·결제·수수료·취소·정산 연동 및 보고서 수입 기능은 확인되지 않았다. 구매 성과는 제휴사의 실제 보고서로 따로 확인해야 한다.

NAS compose 설정상 이벤트 볼륨은 앱의 `runtime/sharelink/events`에서 컨테이너 `/app/affiliate-events`로 연결된다. 로컬 작업본에는 운영 로그가 없다. 담당자의 DSM FileStation 조회에서도 `runtime` 폴더가 목록에 보이지 않았다는 보고를 받았으며, 원인이나 실제 로그 존재 여부를 단정하지 않는다. 접근 권한을 변경하거나 운영 자료를 공개 경로로 옮기지 않았다.

## 비교 시점 분리

계측 결함 수정은 코드 커밋 `7cfc57e`에 포함되며, 공개 확인된 `7a9e140`도 이 수정을 포함한다. `7a9e140`은 이번 배치 변경 전 기준 버전이다. 커밋 시각은 실제 운영 전환 시각과 같지 않다.

1. 계측 수정이 운영에 반영되기 전: hero와 특가의 허용 목록 누락, 숙소의 노출·클릭 위치 불일치가 있어 이후 수치와 직접 비교할 수 없다. 복구 뒤 늘어난 기록을 광고 성과 증가로 보고하지 않는다.
2. `7a9e140` 기존 배치가 운영 중인 기간: 이번 배치 변경 직전의 기록이다. 최초 공개 확인은 2026-11-06 21:51:44 KST였으며 실제 전환 시각을 확정한 값은 아니다. 짧은 이 기간을 안정적인 기준선으로 과장하지 않는다.
3. 이번 배치 변경 후: 최종 SHA와 공개 확인 시각을 배포 기록에 남기고 별도 기간으로 집계한다. 수정 중 수동 확인·테스트 시간도 분리한다. 오래 열린 페이지는 이전 코드로 계속 기록할 수 있으므로 전환 경계 부근에 구버전 이벤트가 섞일 수 있다.

같은 placement·provider·page·productId, 같은 요일 구성과 비교 가능한 노출 조건을 먼저 맞춘다. 가격·재고·특가 교체·유입 구성 차이는 함께 기록한다. 위치와 문구를 한 번에 바꾼 전후 비교만으로 특정 요소의 인과 효과를 확정하지 않는다. 날짜별 합계는 비율의 단순 평균이 아니라 클릭 합계 ÷ 노출 합계로 계산한다. 노출이 없거나 표본이 적으면 결론을 유보한다. 구매를 측정하지 않는 상태에서 클릭 비율을 구매 전환율로 바꾸어 부르지 않는다.

## 오프라인 집계 도구

구성은 `scripts/report-affiliate-events.mjs`, `lib/affiliate-events-report.mjs`, 기존 `lib/affiliate-events.mjs`다. 새 서비스·외부 전송·API 호출·예약 작업 없이 기존 일별 JSONL을 읽는다. 입력 로그와 기존 출력 파일을 덮어쓰지 않는다. 현재 NAS 웹 이미지에는 이 관리 스크립트를 포함시키는 COPY가 없으므로 컨테이너에 이미 설치됐다고 가정하지 않는다. Node.js가 있는 관리 환경에서 세 파일의 상대 경로를 유지해 사용한다.

앱 폴더를 작업 디렉터리로 하고 운영 로그를 읽을 권한이 있는 관리 환경에서 실행하는 예:

```sh
node scripts/report-affiliate-events.mjs --input runtime/sharelink/events --from 2026-11-06 --to 2026-11-12 --output runtime/reports/affiliate-20261106-20261112.json
```

위 기간은 사용법 예시이며 실제 운영 보고서가 생성됐다는 뜻이 아니다. `--output`은 입력 폴더 밖의 **새 파일**이어야 한다. 공개 `public` 폴더·저장소 커밋·공유 문서에 운영 집계 결과를 넣지 않는다. 파일은 POSIX 환경에서 0600으로 생성한다. 기존 파일은 보존하고 다른 파일명을 사용한다.

- `YYYY-MM-DD`는 한국시간 해당 날짜 전체를 포함한다. 양쪽 날짜가 같으면 그 하루다.
- 명시적 ISO 시각은 `--from` 포함, `--to` 제외다. `Z` 또는 `+09:00` 같은 시간대가 필수다. 배포 경계를 나누려면 확인한 실제 시각을 넣는다.
- 파일명은 UTC 일자를 사용하므로 도구는 모든 `YYYY-MM-DD.jsonl` 일반 파일을 읽고 이벤트 시각으로 한국시간 필터를 적용한다. 파일명만 보고 전날 파일을 제외하지 않는다.
- 허용된 날짜·위치·제휴사·상품번호·페이지별 합계만 출력한다. 허용되지 않은 추가 원본 필드를 출력하지 않는다. 깨진 JSON 줄, 잘못된 이벤트·시각, 기간 밖 이벤트를 별도 집계한다.
- 지표명은 **클릭/노출 이벤트 비율**이다. 노출 0이면 비율은 `null`, 반복 클릭으로 100%를 넘을 수 있다. `purchaseCollected`는 `false`다.
- 입력 로그가 없거나 읽지 못하면 실패한다. 이것을 성과 0건이라고 해석하지 않는다. 사용 중인 로그는 계속 추가될 수 있으므로 종료된 기간을 집계하면 결과를 재현하기 쉽다.
