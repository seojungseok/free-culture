# SEO/GEO 정밀 점검 및 수정 결과

점검일: 2026-09-08~09 (KST). 운영 기준: https://mwohaji.kr/, 수정 전 HEAD `938824de525775423ec6660ac1d5f64d3a35b3e4`.
이번 변경은 로컬 production build 검증까지 완료한 상태이며 커밋·운영 배포는 하지 않았다.

## 1. 종합 판정과 4단계

기존 SSR/SSG/ISR, 지역별 고유 제목, canonical, 실제 상세 링크, 공식 데이터 출처는 이미 갖춰져 있다. 전면 개편보다 공유 메타데이터 상속, 로봇 접근 범위, 누락된 sitemap, 방문 판단에 필요한 사실 표현을 수정하는 편이 적절했다. 검색 순위 상승이나 생성형 검색 인용은 보장할 수 없다.

| 단계 | 수정 전 | 조치 및 남은 한계 |
| --- | --- | --- |
| 1 검색의도·탐색·내부링크 | 부분 적용 | 기존 종합 지역 허브 유지, 상세→실제 해당 지역 링크 보강. 자동 코스의 방문 적합성은 추가 검수가 필요 |
| 2 제목·답변·CTA | 부분 적용 | 동명 자치구 제목 구분, 시티투어 탑승 요약, 무료 추정/직선거리 한계 명시 |
| 3 기술 SEO | 일부 잘못 적용 | 공유 제목 상속·전체 query 차단·sitemap 누락·추정 티켓 재고 수정 |
| 4 검증 | 부분 적용 | 빌드/타입/lint/실제 렌더링/HTTP 회귀 검증 완료. 운영 반영 및 검색도구 재수집 검사는 배포 후 필요 |

## 2. 조사 범위와 증거

- 코드: 공개 페이지 유형, 공통 metadata, sitemap/robots, 행사/장소/지역/아이/코스/시티투어/캠핑/맛집/반려동물/특집의 데이터와 렌더링 경로.
- 사전 생성 HTML 873개, 이 중 검사 대상 색인 가능 페이지 869개를 수정 전후 비교했다. 전체 2만여 개의 동적 상세를 모두 렌더링한 것은 아니다.
- 운영 HTTP 22개 샘플은 모두 200. 수정 후 로컬 동일 22개에서도 title/description/H1/canonical/JSON 문법 검사를 통과했다.
- 모바일 390×844와 PC 1280×900에서 메인, 서울/경기/인천/부산/제주, 행사 374432, 장소 809490, 아이 코스 809490, 울산 자연 당일 코스, 부산 레드라인, 반려동물 목록 등 12개씩 실제 렌더링했다. 가로 넘침·관찰된 console error 없음.
- 별도 96개 주요 내부 링크/페이지/robots/sitemap/반려동물 API 요청 모두 200. 잘못된 지역 URL은 의도대로 404. 공개 이미지 16개는 Range GET 206 및 image Content-Type 확인.
- 원시 검사 결과: `seo-before-local.json`, `seo-before-live.json`, `seo-after-local.json`, `seo-after-http.json`, `seo-link-check.json`.

## 4. 실제 수정 사항

1. **공유 메타데이터:** 공통 layout의 고정 OG/Twitter 제목·설명 상속을 제거하여 각 페이지의 실제 metadata를 사용한다. 수정 전 867개가 공유한 Twitter 제목 중복이 검사 후 0건. 홈페이지 URL을 상세 OG URL로 잘못 상속하지 않도록 제거했다. 개별 OG URL이 없는 페이지는 이를 생략하고 기존 canonical을 유지한다.
2. **동명 자치구:** 강서구·남구·동구·서구·중구 등 다른 시도에도 존재하는 18개 지역 데이트 제목에 부모 지역을 추가했다. 실제 중복 제목 4그룹은 0으로 감소. 그 외 사전 생성 페이지 검색 제목과 모든 canonical은 변경하지 않았다.
3. **robots:** `/*?*` 전체 차단이 `?dpl` 스크립트·최적화 이미지·검색 페이지의 noindex 확인까지 방해할 수 있어 기존 목록 필터 경로만 제한한다. 공개 API/Next 리소스는 접근 가능. AI 학습 정책을 새로 설정하거나 별도 파일을 만들지 않았다.
4. **sitemap:** 기존 season, camping collections, 아이 코스 1,544개, 캠핑 묶음 66개, 실제 반려동물 상세 121개를 포함했다. 현재 장소 데이터에 없는 발행글 ID는 제외해 잘못된 상세/리다이렉트 링크를 방지했다. 9월 8일 빌드 기준 23,803 URL; 9월 9일 재실행은 날짜 의존 행사 목록 변동으로 23,802 URL. 운영 비교값 22,112. 중복·query·검색/보관함·잘못된 ID 없음, 50,000개 제한 이내. 가짜 갱신일은 추가하지 않았다.
5. **반려동물:** 기존 캐시의 실제 장소 12개를 서버 렌더링 초기값으로 재사용한다. 후속 API 실패/빈 응답으로 이 초기 콘텐츠가 사라지지 않도록 한다. 프론트 필터와 기존 API 유지.
6. **행사:** 정확히 확인된 무료 또는 단일 가격만 Offer로 표현. 최고가 단독 사용과 추정 `InStock` 제거. 무료 추정은 무료 확정과 구별. 종료 안내, 의미 있는 time, BreadcrumbList 추가. 종료 행사 URL은 삭제하지 않는다.
7. **지역:** 기존 17개 종합 허브 구조·제목·canonical 보존. 실제 해당 주말 날짜를 표시하고 관광지 운영일 재확인 안내를 추가했다.
8. **시티투어:** 원본 탑승지와 기존 엄격 매칭 경유지를 질문형 핵심 요약으로 표시한다. 기존 사진 매칭/캐시·출처·기준일 유지. 중첩 사진 제목을 H3로 정리하고 보관함에도 실제 대표사진을 저장한다. 가짜 FAQ schema·추천 하차시간은 생성하지 않았다.
9. **아이 코스:** 좌표로 만든 구간의 직선거리 합계를 도보/차량 시간으로 오인하지 않도록 설명한다. 확인되지 않은 반나절 소요 문구를 실제 경유지 설명으로 교체했다.
10. **내부링크:** 공통 NextStop을 쓰는 장소·행사·캠핑 상세에서 해당 시도 허브로 연결. 아이 코스의 보이는 breadcrumb와 JSON-LD 지역 경로를 맞췄다. 다른 지역이나 관련 없는 링크를 넣지 않았다.

## 5. 보존한 구조와 GEO 판단

기존 검색 URL, canonical, 메인·지역 검색 제목, 페이지 라우팅, 상세 정보/API, 사진 캐시 및 사실 기반 매칭을 보존했다. 이미지 옆에 같은 링크 제목이 이미 있는 장식 이미지의 빈 alt는 중복 낭독을 피하기 위해 유지했다. 방문자별 추정 후기·가짜 인기순·리뷰·별점·가격·주차 가능·AI 인용 보장을 추가하지 않았다.

[Google AI 검색 안내](https://developers.google.com/search/docs/appearance/ai-features)에 따라 별도의 AI 전용 schema/파일보다 크롤링 가능한 본문, 실제 질문의 답, 내부링크, 표시 내용과 일치하는 구조화데이터에 집중했다. [Google 행사 schema](https://developers.google.com/search/docs/appearance/structured-data/event), [canonical 안내](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls), [네이버 robots 안내](https://searchadvisor.naver.com/guide/seo-basic-robots)를 기준으로 검토했다. JSON 문법/내부 규칙 검증은 통과했지만 검색엔진 리치결과 승인이나 인용을 뜻하지 않는다.

## 6. 방문자 변화와 성능

- GA/Search Console/네이버 서치어드바이저의 실제 기간별 유입·색인·노출 데이터에 접근할 수 없어 방문자 감소 원인은 확정 불가.
- 검사한 운영 HTML에는 GA gtag가 보이지 않았다. 기존 Analytics는 환경변수에 의존한다. 임의 측정 ID를 넣지 않았다. 이것이 최근 제거됐다는 증거는 없다.
- 공개 방문자 카운터는 브라우저 세션 기준이고 외부 서비스 실패도 숨겨질 수 있어 검색 유입/순방문자 수와 동일하지 않다.
- robots의 query 일괄 차단은 기술적 위험이지만 실제 트래픽 하락 원인이라는 증거는 아니다.
- 새 외부 API 호출이나 클라이언트 라이브러리 없음. 공통 First Load JS는 103 kB로 유지. 반려동물의 12개 초기 카드만 작은 SSR 증가를 수반한다.
- 기존 맛집/주말/아이/플래너 HTML은 큰 편이며 앞으로 목록 초기 전송량을 실제 waterfall에 근거해 줄일 여지가 있다. 이번 작업에서 데이터/필터를 무리하게 바꾸지 않았다.
- 공개 PageSpeed API는 429 quota 응답. 실제 사용자 LCP/CLS/INP 수치 및 경쟁 사이트와의 수치 비교는 미확인. 이미지 크기/지연 로딩 기존 방식을 유지했지만 수치상 CWV 개선을 주장하지 않는다.

## 7. 검증 결과 및 잔여 항목

- `npm run build`: 통과, 873개 사전 생성. `npx tsc --noEmit`: 통과.
- `npm run lint`: 오류 없음. 기존 img 최적화·Hook dependency 경고는 남아 있다.
- `git diff --check`: 통과. 기존 URL/canonical 변경 없음. 수정한 검색 제목은 동명 자치구 18개만.
- `node scripts/testSeo.cjs`: 가격/추정 재고 금지/sitemap/robots/무료 추정 검증 통과.
- `node scripts/testRegionCity.cjs`, `node scripts/testParking.cjs`: 기존 지역·사진 매칭·주차 경계/정보 부재 처리 회귀 검사 통과. 실시간 주차 외부 제공률을 새로 검증한 것은 아님.
- `node scripts/testSeoHttp.mjs`: 96개 요청, 잘못된 경로 404, 이미지 16개 통과. 샌드박스의 외부 네트워크 실패는 권한 있는 공개 HTTP 재검사로 구분했다.
- 서울 지역 나들이 필터 전환 정상. 시티투어 보관함 저장 후 제목과 실제 대표사진 노출 정상.
- 전통시장 목록의 client/API 의존, 자동 생성 코스의 실제 보행/동선 적합성, 상세 원본의 최신 운영 조건은 추가 검수 대상이다. 모든 외부 API와 모든 동적 상세를 전수 검사했다고 보지 않는다.
- 배포 미실행. 운영 robots/sitemap/OG 반영과 Search Console 재수집·유입 추적은 운영 배포 후 별도 확인이 필요하다.

## 8. 우선 쌓을 콘텐츠 5개

1. 서울·경기 아이 연령별 나들이: 실제 예약 필요 여부, 유모차/화장실, 이용 제한과 기준일.
