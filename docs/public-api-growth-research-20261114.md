서울시 예약 자료에는 현재 공원 탐방·목공·박물관 교육 같은 체험 사례가 확인된다. ‘장소가 어디인가’에 더해 ‘지금 신청할 수 있는가, 누구와 갈 수 있는가’에 답할 수 있어 첫 도입 대상으로 추천한다. 기상·대기 자료는 장소 선택을 돕는 보완 기능이며 그 자체의 페이지 수를 늘리는 용도로 쓰지 않는다.

## 첫 기능의 구체적인 범위

1. 서울 문화체험만 수집해 `sourceId`, 장소·좌표, 대상, 이용 기간, 접수 기간, 제공처 상태, 유·무료 원문, 공식 URL, `checkedAt`을 저장한다. 원문 상태를 별도로 보존하고 예상 좌석을 만들지 않는다.
2. 진행·접수 기간과 대상이 확인된 무료 체험만 모은다. 종료·접수마감은 현재 신청 목록에서 제외하되 기존 공개 URL은 보존하고 상태를 표시한다. 제공처 상태가 없으면 ‘접수 상태 확인 필요’로 둔다.
3. 초기에 서울 모음 1개와 실제 자료가 충분한 지역 모음 소수만 공개한다. 결과 없는 지역×대상 조합은 색인 페이지로 대량 생성하지 않는다.
4. 기존 ‘아이와’, ‘이번 주말’, 장소 상세에서 관련 체험으로 연결한다. 행사와 예약 정보가 같은 경우 두 상세페이지를 만들기보다 기존 글에 예약 안내를 보강한다.
5. 유효한 키·활용승인·원문 필드·이용 조건을 확인한 뒤 연결한다. 이번 작업에서는 새 기관 키를 발급하거나 미연결 API의 자료를 홈페이지에 이미 넣었다고 표시하지 않는다.

## 조회수 하락 원인과 효과 측정

이번 브라우저의 Search Console은 로그인 화면이어서 검색어·페이지별 실적을 읽지 못했다. GA 실적도 조회하지 않았다. 따라서 계절 변화, 검색 노출 감소, 클릭률, 측정 문제 중 어느 것이 원인인지 확정하지 않는다.

[Google의 공식 유입 감소 점검 문서](https://developers.google.com/search/docs/monitor-debug/debugging-search-traffic-drops)는 Search Console에서 기간·검색어·페이지·기기를 나누어 클릭과 노출, 순위의 변화를 비교하도록 안내한다. 실제 확인 때는 최근 28일을 직전 28일과 비교하고 요일을 맞추며, 가능하면 전년 같은 계절도 본다. 클릭만 줄었는지 노출도 줄었는지부터 구별한다.

- 우선 볼 지표: 지역·무료체험 모음의 검색 노출, 클릭, CTR, 평균 순위와 원문 예약 안내 클릭. 내부 준비물 구매 클릭과 예약 링크 클릭은 별개로 집계한다.
- 공개 전 기준치를 남기고 2주·4주 뒤 같은 페이지 묶음을 비교한다. 단순 증감만으로 새 API가 원인이라고 단정하지 않는다.
- 예산을 먼저 쓸 곳은 접수 가능한 체험을 찾는 기능과 기존 글의 구체적인 설명이다. 같은 원문을 문장만 바꾼 글이나 날씨별 지역 페이지를 대량 만드는 방식은 권하지 않는다.
- 새 데이터가 들어가도 검색 노출·조회수·제휴 수익 증가는 보장되지 않는다. 이번에 완료한 것은 수집 상태 확인, 준비가이드 개선, 최신성 점검 기능과 도입 조사다.

## 최신성 유지에 반영한 사항

`/about#data-updates`에서 자료별 마지막 목록 수집 시각·주기·저장 건수를 표시하고 `/api/data-status`에서 같은 기준을 조회할 수 있게 했다. 일일·주간 작업은 외부 API를 추가 호출하지 않고 저장 기록을 점검한다. 일일 자료 36시간, 주간 자료 9일이 지나거나 수집 기록이 없으면 실패로 알리고, 일부 갱신 보류는 경고와 실제 상태로 남긴다. 실패한 데이터를 당일 확인으로 덮지 않는다.
