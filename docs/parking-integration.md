# 주차정보 통합 설계 및 검증

## 선택한 활용

관광지/문화시설 상세, 진행 예정·진행 중 행사 상세, 여행코스의 **실제 첫 방문지**에 동일 시도·직선 700m 이내 주차 후보를 최대 3개 노출한다. 사이트 기존 방문정보와 인근 장소 추천을 유지하며, 코스 중심 좌표를 출발지로 오인하지 않는다. 외부 API가 실패해도 상세페이지 생성에는 영향이 없다.

시티투어 20개는 탑승지의 확정 좌표가 없어 제외했다. 경유지의 좌표를 탑승지 대신 사용하는 매칭은 하지 않는다. 캠핑장은 자체 주차 안내가 중요하므로 이번 범위의 우선 적용에서 제외했다. 같은 이유로 기존 플래너의 '주차 가능' 필터를 근처 주차 후보로 덮어쓰지 않는다.

## 실제 API 관측

[공식 명세](https://www.data.go.kr/data/15099883/openapi.do)의 서비스는 `https://apis.data.go.kr/B553881/Parking`이다. 인증키는 서버 `PARKING_API_KEY`, 없으면 기존 `DATA_GO_KR_KEY`를 사용한다. 브라우저나 데이터 파일로 전달하지 않는다.

- 시설: `PrkSttusInfo`; `prk_center_id`, 명칭/주소/시도/시군구, `prk_plce_entrc_la/lo`, `prk_cmprt_co`.
- 운영: `PrkOprInfo`; 같은 ID, `basic_info` 기본시간/요금, `opertn_bs_free_time`, 요일별 시작/종료, 정액요금 정보.
- 실시간: `PrkRealtimeInfo`; 같은 ID, `pkfc_Available_ParkingLots_total`, `pkfc_ParkingLots_total`. 관측 응답에 제공기관 갱신 시각은 없다.
- 목록 전체 개수 응답은 시설/운영 각각 1,767,934, 실시간 787,237이었다. **중복이 많아 고유 주차장 수 또는 실시간 제공률로 해석하지 않는다.** 검증된 표본의 연결률만 `data/parking.json`의 `quality`로 기록한다.
- 같은 ID에 다른 좌표가 있는 사례, 한 좌표에 여러 이름, 좌표 공란, 시설·운영 불일치를 확인했다. ID를 임의로 잘라 병합하지 않으며 충돌을 제외한다.
- 기본요금 0원만으로 종일 무료를 판정하지 않는다. 무료시간은 해당 값만 표시한다. `000000–000000`은 미확인이고, 명시된 `000000–240000`만 해당 요일의 24시간 구간으로 읽는다. 공영/민영 구분 필드는 관측하지 못했으므로 별도 분류하지 않는다.

## 호출·캐시 설계

시설·운영은 각 80개의 제한 표본 페이지(10개/페이지)를 수집한다. 페이지당 재시도는 최대 1회, 동시 작업은 최대 4개. 성공 응답은 로컬 7일 재사용 캐시에 둔다. 주간 워크플로에 연결하며 실패/검증량 급감 시 이전 공개 스냅샷을 유지한다. 수집 범위는 전국 전수가 아니며 누락은 '주차장 없음'을 뜻하지 않는다.

상세페이지 조회는 외부 호출 **0회**. 실시간은 알려진 ID의 버튼을 누를 때만 고정된 최대 3개 페이지 중 하나를 가져온다. 방문자별 3종 호출을 하지 않는다. `unstable_cache` 900초로 성공·실패 모두 공유하고 같은 인스턴스의 중복 요청도 합친다. 새 값이 없거나, ID가 없거나, 총면수 충돌/15분 초과 캐시이면 미제공 상태로 처리한다. 서버 타임아웃은 6초, 브라우저는 9초다.

예상: 시설/운영은 평일 각각 0회, 주간 갱신일 각각 보통 80회(최대 160회). 실시간은 사용하지 않으면 0회, 3개 캐시 페이지가 하루 종일 사용되는 정상 캐시 조건에서 약 288회/일 + 주간 표본 3회. 콜드스타트·배포·분산 동시성으로 이론값보다 늘 수 있으므로 엄격한 전역 계량이 필요할 규모에는 별도 영속 quota 저장소가 필요하다. 전역 일일 카운터가 구현됐다고 주장하지 않는다.

## 검증 명령

`node scripts/probeParking.mjs`: 각 API 제한 조회, 인증키 출력 없음.

`node scripts/collectParking.mjs`: 공개 스냅샷 생성, 수집량·품질 통계 출력.

`node scripts/testParking.cjs`: 지역·거리·좌표·ID/운영 충돌, 0/미제공, 실시간 충돌, 실제 관광지/행사 표본 매칭.

`node scripts/testParkingCache.cjs`: 동일 페이지 공유 호출, 900초 캐시, 미등록 ID 0회, 실패 캐시/페이지 격리.

`npx tsc --noEmit`, `npm run lint`, `npm run build`.

`node scripts/testParkingHttp.mjs`: 로컬 production 서버 3210에서 메인/보관함/상세 7개 경로 200, 상세 canonical·JSON-LD 유지, 잘못된 ID 처리, 공개 번들/HTML/스냅샷 인증키 미노출을 검사한다.

## 최종 검증 결과 (2026-09-08)

- 검증 스냅샷: 12개 시도, 시설 407곳, 공통 ID 운영 연결 102곳, 실시간 목록 연결 7곳(표본의 1.72%; 전국 제공률이 아님).
- 마지막 수집 실행: 시설 99회 / 운영 92회 / 실시간 3회. 앞선 응답 조사·재시도 호출은 이 실행별 집계에 포함되지 않는다. 시설·운영 API 일부 타임아웃과 실시간 1페이지 타임아웃이 있어 제한 표본으로 저장했다.
- 원본 콘텐츠 매칭: 관광지 368곳, 행사 191건(종료된 행사 포함한 검사 수), 코스 첫 방문지 76건(발행 여부 제외 전). 실제 화면은 발행·행사 종료 조건도 적용한다.
- 실제 브라우저: 인천 강화 원도심 스토리워크(`/places/spot/2684765`), 서울 낙원동 아구찜 거리(`/places/spot/699222`), 부산 관음사(`/places/spot/2785265`), 울산 첫 방문지 코스(`/course/c/ulsan-nature-day-1uttc9i`), 서울 행사(`/event/384927`). 주소·동일 시도·직선 거리와 노출 내용을 대조했다. 제공기관 좌표 자체의 현장 정확성까지 보증하는 검사는 아니다.
- 390px/360px 모바일, 1280px PC에서 주차 영역과 운영정보 펼침을 점검했다. 검사 화면의 가로 넘침·콘솔 오류·깨진 이미지 없음. 기존 메인 및 보관함 HTTP 200.
- 탑골공원 ID `03140-11191-00001-00-1` 실제 조회: 잔여 2/총 2면, API 조회 시각 `2026-09-08T12:57:16.049Z`. 연속 조회도 동일한 시각을 반환해 공유 캐시를 확인했다. 이 숫자는 테스트 시점 값이며 현재 잔여면을 보장하지 않는다.
- API 실패/실시간 미제공/0면/충돌/타지역/700m 초과/미등록 ID/900초 캐시는 자동 테스트 통과. 공개 출력 105개 파일과 검사 HTML·데이터에서 인증키 미노출 확인.
- 실제 스냅샷으로 production build, TypeScript, lint, `git diff --check` 통과. lint의 기존 이미지/Hook 경고는 남아 있다.

## 확장 조건 / 남은 제한

공영 여부·종일 무료·휴무·실제 제공기관 갱신 시각은 현재 필드만으로 확정할 수 없다. 무료주차 모음, 주차 편한 드라이브 순위, 시티투어 출발지 매칭은 이 정보를 검증한 뒤 확장한다. API의 표본 편향/중복 때문에 현재 기능을 전국 주차 검색으로 광고하지 않는다. 기존 URL·canonical·메타데이터·JSON-LD는 변경하지 않는다.

ESLint 도입 후 기존 이미지/Hook 경고는 남아 있다. npm audit에서 기존 Next/PostCSS/sharp/nanoid 계열 high 4건을 확인했으나, Next 16으로의 메이저 업그레이드는 이번 주차 통합 범위를 벗어나 수행하지 않았다.
