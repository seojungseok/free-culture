# 자동 글 통합 배포 — 2026-09-15

일반 글·여행코스·시티투어·준비물·검수된 입장권과 기존 입장권 보장 근거를 `daily.yml` 마지막 커밋 한 번에 반영한다. 매일 한국시간 05시 작업을 시작하고, 작성·검수·갱신이 끝난 뒤 한 번 배포한다. 시작시각은 공개시각이 아니며 Actions 지연과 생성 시간이 포함된다.

- `waug.yml`의 별도 05/06시 자동 배포를 없애고 수동 관리 기능은 유지한다. 입장권 발행은 일일 작업 안에서 최대 3회 재시도하며, 실패하면 다음 일일 실행 또는 수동 작업에서 재시도한다.
- 기존 상품·본문·이미지·권리 검수와 발행 한도는 기존 스크립트를 그대로 사용한다. 입장권 실패로 일반 글을 막지 않는다. 혜택 근거 갱신도 독립 단계로 실행하며, 기존 만료 검사와 실패 시 배지 제외 규칙을 보존한다.
- 일일 작업·입장권 수동 관리·작성 중간 저장 작업은 같은 concurrency group으로 직렬화한다. 동시 실행으로 발행 이력을 덮어쓰지 않는다.
- 비공개 큐·조사·작성 기록만 바뀌면 Vercel 빌드를 생략한다. 공개 글·혜택·목록 데이터·이미지·코드 변경은 반드시 빌드한다. 마지막 성공 배포 SHA와 비교하고 SHA/이력 오류는 빌드로 처리한다.
- push 직후 이전 운영 버전을 무효화하던 revalidate 호출을 제거한다. 로컬 JSON은 새 빌드에 포함되므로 이전 배포에서 캐시 무효화만 실행해도 신규 JSON을 공개할 수 없다.
- push 실패/충돌을 성공으로 기록하지 않는다. 작성된 글을 재생성하지 않고 동일 커밋 저장만 재시도한다.

오늘 자동 신규 글은 관광지 10개·시티투어 7개로 이미 하나의 배포에 들어갔다. 별도 중간 저장은 큐·후보의 예약 계획만 변경했고, 별도 입장권 작업은 기존 보장 근거만 갱신했다. 이번 변경은 이 별도 빌드들을 줄이는 조치다. 신규 이미지 첫 변환, 방문 트래픽, 글 생성 API 과금은 계속 발생하며 전체 절감률 또는 추가 $5 이내 결과는 실제 Vercel Usage 비교 전에는 확정하지 않는다.
