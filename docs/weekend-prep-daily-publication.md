# 주말 준비물 추가 5편 예약

## 서버 발행과 원고 준비는 별개

기존 `daily.yml`의 한국시간 05:00 시작 일정과 일반 글 30편, 입장권·체험 별도 20편 작업은 변경하지 않는다. 주말 준비물 예약 발행 단계만 추가해 기존 통합 커밋/배포에 포함한다. 별도 상시 서버·DB·방문자 API 요청은 추가하지 않는다. GitHub 작업 시작 지연과 기존 작성 작업, Vercel 배포 소요 때문에 공개 시각은 05:00 이후일 수 있다.

주말 준비물의 기존 매시간 23분 빈 실행은 제거한다. `weekend-prep.yml`은 수동 복구 전용이며 통합 일일 작업과 동일 동시실행 그룹·동일 발행기·동일 5개 한도를 쓴다. 다른 카테고리 예약은 변경하지 않는다.

`publisherEnabled:true`는 검토된 예약 원고의 서버 발행을 뜻한다. `generationEnabled:false`와 `enabled:false`는 자동 원고 생성이 아직 연결되지 않았음을 뜻한다. 원고가 없는데 하루 5편 자동 생성·발행 완료라고 표현하지 않는다.

## 원고를 예약하는 방법

1. `planDaily(config, 대상일 T05:00:00+09:00)`의 다섯 슬롯을 사용한다. 날짜별 전체 5편이며 여섯 분류가 순환한다. 최초 18편 재작성/교체는 별개이며 일일 슬롯으로 돌려막지 않는다.
2. 글마다 서로 다른 실제 상품, 정보형 원고, 감성 한글 썸네일을 포함한 이미지 3~4장, 사진마다 실제 상품 3~4개의 + 태그를 작성·검토한다. 상품 API는 기존 공용 쿠팡 gateway만 사용한다. 요청/조회량 각 직전 60초 10 이하, 최소 간격 6.1초를 유지한다.
3. 본문·상품·이미지·링크 검사를 통과한 글에 `dailySlotId`를 슬롯의 id, `publishAt`을 슬롯의 publishAt, `category`를 슬롯 분류로 저장한다. 상태는 `scheduled`다. 미완성은 `draft`로 남긴다. 관련 이미지도 같은 커밋에 포함한다.
4. 서버는 해당 날짜 05:00 이후 예약 글만 다시 검사한다. 실패한 글만 `held` 기록하고 다음 슬롯을 처리한다. 1편 실패면 나머지 4편을 발행한다. 링크 확인 실패를 임의로 승인하거나 상품 검토 플래그를 자동으로 true로 바꾸지 않는다.
5. `dailyReceipts`를 글 데이터와 함께 커밋한다. 동일 날짜 재실행 시 완료·실패한 슬롯을 재처리하지 않는다. 비어 있는 슬롯은 성공으로 기록하지 않는다. 지난 날짜를 다음 날 몰아 발행하지 않는다.

운영 중인 workflow와 수동 작업은 같은 데이터를 동시에 쓰지 않는다. 최신 main을 기준으로 작성하고 충돌 시 자동 덮어쓰기·강제 push를 금지한다. 발행 기록 커밋 또는 배포가 실패하면 완료로 보고하지 않는다.
