# 일일 공공정보 수집 실패 수정

2026-10-03 실패 실행: https://github.com/seojungseok/free-culture/actions/runs/37078076987

## 확인된 원인

- 축제 상세 보강은 첫 4회, 장소 소개 보강은 첫 1회에서 제공기관 한도 오류로 중단됐다. 자체 설정 예산 90회·20회가 소진된 상황은 아니다.
- 축제 목록 5회, 지역 축제, 문화행사, 반려동물 기본·상세 수집은 성공했고 `28e8b8e`에 저장됐다. 홈페이지 배포 실패를 알리는 메일은 아니다.
- 키 값을 출력하지 않은 제한 조회에서 `detailCommon2`의 HTTP 429와 `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR`를 확인했다. 공공데이터포털은 이를 일일 호출 허용량 초과로 설명한다: https://www.data.go.kr/tcs/dss/selectErrCodePopupView.do
- 장소·음식점 상세를 열 때 공통정보·사진·요금을 가져오는 경로가 남아 있었다. 방문에 따른 요청은 수집 스크립트의 예산 밖에서 일어났다. 정확히 어느 클라이언트가 호출량을 소진했는지는 제공기관 계정의 사용내역 없이는 확정할 수 없다.
- NAS는 Next 캐시 볼륨을 유지하며, 장소·음식점 상세를 빌드 시 전량 생성하지 않는다. 매일 배포가 모든 상세 API를 호출했다는 근거는 없다.

## 수정

- 공개 화면의 기본 동작은 저장된 공공정보·요금·사진을 사용한다. 인증키가 설정되어 있어도 방문 시 TourAPI를 호출하지 않는다. 이전 주소·글·대표 사진은 유지한다.
- 관광지·음식점은 번갈아 수집한다. 소개·홈페이지는 화~일요일 최대 100회, 추가 사진은 최대 30회(각 재시도 포함) 보강한다. 월요일은 주간 수집과 한도를 나눠 각각 20회·10회로 줄인다. 정상 빈 응답은 반복 조회를 피하도록 기록하며 기존 사진을 지우거나 예전 정보의 확인일을 바꾸지 않는다.
- 제공기관 한도로 중단한 선택적 상세 보강은 종료 코드 75로 구분한다. 작업 래퍼는 이를 명시적인 경고와 `deferred` 기록으로 남겨 다음 예약 실행에서 재개한다. 다른 인증키로 한도를 우회하지 않는다.
- 인증 실패, 잘못된 응답, 연결 실패, 자체 예산 오류는 여전히 작업 실패로 보고한다. 제공기관 한도로 연기된 데이터를 갱신 완료로 표시하지 않는다.
- 주간 일반 TourAPI 예산은 850회다. 월요일 일일 130회와 합쳐 최대 980회이고, 다른 날은 일일 최대 230회다. 다른 클라이언트나 더 엄격한 제공기관 제한이 있으면 제공기관 결과가 우선한다.
- 축제 목록·문화행사·반려동물 정보는 매일 수집하고, 축제 상세는 7일·장소 소개와 사진은 30일 기준으로 오래된 확인 결과부터 재점검한다. 모든 항목을 당일 확인했다고 표시하지 않는다.
- 일일 수집은 한국시간 05:17, 주간 수집은 월요일 03:23 실행 예정이다. GitHub는 정각 혼잡과 예약 지연을 안내한다: https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule
- NAS는 매일 00:15~23:15 매시간 새 커밋을 확인하도록 설정한다. 작은 커밋 메타데이터만 먼저 확인하고 변경이 있을 때만 다운로드·배포한다. 배포 대상 커밋을 고정해 수집 중 새 커밋이 생겨도 배포 버전을 잘못 기록하지 않는다.
