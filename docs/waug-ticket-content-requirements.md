### 1. 가장 중요한 목표

독자가 “광고를 읽었다”는 느낌보다 “갈 만한 곳과 방문에 필요한 정보를 알았다”는 느낌을 받도록 해줘.

그 정보를 읽고 방문하고 싶어진 사람이 티켓을 확인할 때, 반드시 아래에 제공한 내 와그 제휴링크를 클릭하도록 연결해야 한다.

제휴 관계는 글 최상단에 명확히 안내하되, 본문은 과장된 홍보 대신 실질적인 여행 정보로 구성해줘. 수수료는 단순 클릭이 아니라 와그의 구매 인정 조건에 따라 발생하므로, 클릭과 구매 실적을 혼동하지 마.

### 2. 글쓰기 방법은 실제 사례를 조사해서 네가 판단

국내 블로그·여행 사이트·유튜브와 해외 블로그·여행 사이트·유튜브에서 다음을 잘하는 실제 사례를 조사해줘.

“독자에게 유용한 여행 정보를 제공하면서, 문맥상 자연스럽게 입장권 확인과 예약으로 이어지는 콘텐츠.”

해외자료를 참고하라는 것은 해외 여행지를 소개하라는 뜻이 아니다. 정보 전달 방식과 글쓰기 방식을 배우라는 뜻이다.

실제 본문이나 영상 내용·자막을 확인하고, 참고 URL과 배운 점을 간단히 기록해줘. 검색 요약만 읽고 영상을 분석했다고 하지 마.

정보의 구체성, 신뢰 형성, 장소의 매력 전달, 불편한 점 설명, 이미지 활용, 구매 버튼의 문맥과 위치를 비교해줘. 공개되지 않은 구매 전환율을 추정해서 성공 사례라고 단정하지 마.

그 결과를 바탕으로 우리 사이트와 각 장소에 적합한 제목·문체·분량·구성·버튼 문구를 네가 결정해줘.

고정된 목차나 동일한 도입부를 모든 글에 반복하지 마. 문장을 베끼거나 상품 설명을 단순히 바꿔 쓰지 마. 장소마다 독자가 궁금해하는 점을 찾아 다르게 작성해줘.

직접 방문한 것처럼 경험을 꾸미지 말고, 확인한 사실에 기반해 자연스러운 한국어로 작성해줘. 장점뿐 아니라 방문 전 알아야 할 제한과 아쉬운 점도 필요한 만큼 설명해줘.

### 3. 장소마다 직접 조사한 후 작성

아래 제휴링크에 접속해 실제 연결 상품과 장소를 확인해줘. 이어서 시설 공식 홈페이지, 우리 사이트의 기존 공공데이터, 신뢰할 수 있는 최신 자료를 대조해줘.

방문 결정에 필요한 정보를 장소별로 선별해줘. 운영시간·휴무·주소·주차·요금·연령 및 키 제한·예약 조건·포함 사항 등은 확인된 내용만 사용하고 출처와 확인일을 관리해줘.

상품명에 붙은 ‘특가’, ‘콜라보’, ‘미들시즌’, 지점 수 등이 지금도 유효하다고 가정하지 마.

다른 시간권과 패키지를 같은 상품으로 취급하지 말고 차이를 확인해줘. 같은 장소는 원칙적으로 하나의 충실한 글에 이용권 선택지를 연결하고, 지점이나 방문 목적이 실질적으로 다르면 별도 글을 작성해줘.

### 4. 입장권·체험 이미지 확보와 장소별 대표 썸네일 제작

#### 4.1 본문 사진과 대표 썸네일 구분

본문에는 해당 와그 상품에서 제휴 홍보에 사용 가능한 실제 사진과 우리 홈페이지에 연결된 공공정보·관광사진 API 및 보유 자료의 실제 사진을 활용해줘.

먼저 기존 프로젝트의 이미지 API, 저장소, 캐시, 관광지 식별 정보를 확인해 활용하고, 이미 보유한 연동을 확인하지 않고 새 API부터 요구하지 마. 장소명뿐 아니라 주소·지점·촬영지를 대조해 정확히 해당 장소의 사진을 선택해줘. 주변 관광지 사진은 시설 내부 사진처럼 보이지 않도록 설명해줘.

본문은 대표 썸네일에 사용한 사진과 다른 장면을 우선 사용하고, 확보 가능하면 3장 안팎을 자연스럽게 배치해줘. 사진 수를 채우려고 엉뚱한 사진이나 같은 사진을 반복하지 마.

별도로 외부 유입을 위한 대표 썸네일을 장소 글마다 딱 1장씩 제작해 업로드해줘. 같은 장소의 시간권·이용권·패키지마다 중복 제작하지 마. 장소·지점과 연결 글을 기준으로 관리하고, 기존 원칙에 따라 별도 장소 글로 분리한 경우에만 글별로 제작해줘.

#### 4.2 실제 사진을 바탕으로 한글 문구와 디자인 추가

확인된 글 내용과 해당 장소의 실제 사진을 바탕으로 한글 문구와 디자인을 더해줘. 장소의 매력을 표현하면서 유용한 여행 정보를 기대하게 하고, 과장된 광고나 낚시성 문구는 피해야 해.

문구와 디자인은 장소마다 자체 판단해줘. 긴 글 제목을 그대로 넣지 말고 짧고 읽기 쉽게 구성하며, 모바일에서도 읽히도록 글자는 크고 간결하게 넣어줘.

제작 전에 실제 본문을 읽고 장소의 특징, 함께 가기 좋은 대상, 즐길 거리, 방문 준비 정보 중 충분히 다룬 내용을 골라줘. 문구 후보를 내부적으로 비교해 자연스러움·장소 특성·본문 일치·클릭할 이유가 가장 좋은 안을 선택하고, 매번 사용자에게 선택을 요구하지 마.

장소명은 명확히 보여주고 핵심 문구는 한눈에 뜻이 전달되는 자연스러운 1~2줄로 작성해줘. 보조 문구는 꼭 필요할 때만 한 줄 추가해줘. ‘몇 시에 갈까?’, ‘어디로 갈까?’, ‘여기 어때?’ 같은 막연한 질문을 반복하지 마. 구매보다 방문에 대한 관심을 먼저 만들고, 구매·특가·예약 유도나 이용권 종류 나열을 대표 문구로 사용하지 마. 이용권 비교가 글의 핵심인 경우에만 보조 정보로 활용해줘.

억지 감성, 번역투, 과장된 감탄, ‘무조건’, ‘역대급’, ‘안 가면 손해’를 피하고 구체적인 정보를 기대하게 해줘. 야경·아이 동반 적합성·할인·계절 행사·운영 정보는 본문에서 확인하고 충분히 다룬 경우에만 문구에 사용해줘. 모든 장소에 같은 문구를 일괄 적용하지 마.

실제 장소 사진을 충분히 크게 보여줘. 넓은 단색 배경이나 큰 글씨 때문에 사진이 작은 삽화처럼 밀려나지 않게 해줘. 장소명과 핵심 문구의 우선순위를 구분하고 불필요한 장식·아이콘·보조 문구는 빼줘. 사진 출처는 읽을 수 있게 표시하되 핵심 문구와 구분해줘. 모바일 크기에서도 사진의 매력과 글자가 함께 전달되는지 확인해줘.

실제로 없는 시설·풍경을 생성하거나 합성해 해당 장소의 모습처럼 보여주지 마. 이미지 생성·편집 기능을 쓰더라도 실제 시설과 풍경을 사실과 다르게 바꾸지 마.

와그 공식 가이드와 공공사진별 이용조건에서 게시뿐 아니라 편집·상업적 제휴 홍보·외부 공유에 필요한 사용 범위까지 확인해줘. 와그 후기 이용자 사진은 자동으로 허용된 것으로 간주하지 마. 필요한 출처·촬영자·라이선스 표시를 유지하고, 공유 이미지 자체에도 표시가 필요한 조건이면 이미지 안에 포함해줘.

장소 일치나 사용·편집 권한이 확인되지 않은 사진은 보류하고 검증된 대체 사진을 찾아줘. 본문 게시만 허용되고 편집이 허용되지 않는 사진은 썸네일 제작에 사용하지 마.

공공사진의 출처는 제목·핵심 문구 바로 아래에 두지 말고 이미지 오른쪽 하단에 작고 단정하게 배치해줘. 가장자리 여백과 배경 대비를 확보해 읽을 수 있게 해줘. 공공사진을 편집하거나 글씨를 합성한 경우에도 필요한 원본 출처를 유지해줘. 공공사진을 사용하지 않고 처음부터 생성한 이미지에는 ‘사진: 경기도 · 공공누리 1유형’ 등 해당 없는 출처를 넣지 마. 이 출처 규칙이 실제로 없는 시설·풍경을 해당 장소처럼 생성해도 된다는 뜻은 아니며, 실제 장소 일치 원칙은 그대로 유지해줘.

#### 4.3 한 장으로 모바일·PC·외부 공유 공통 사용

최종 대표 썸네일은 기본 1200×630px로 제작해줘. 저장한 동일 이미지 주소를 글 대표 이미지, 목록 카드, 카카오톡 등 외부 공유용 OG 이미지에 재사용해줘. 용도별 복사 파일을 별도로 저장하지 마.

모바일·PC의 대표 이미지와 목록 카드 영역은 원본 비율을 유지해 전체 이미지가 잘리지 않도록 표시해줘. 고정 높이와 cover 방식으로 이미지를 잘라내지 말고, 원본 비율 표시 또는 contain 방식 등 기존 구성에 맞는 방법을 사용해줘.

외부 플랫폼의 일부 잘림에 대비해 핵심 문구와 피사체를 중앙 안전영역에 배치하고, 가장자리에는 중요한 정보를 두지 마. 외부 플랫폼의 크롭을 완전히 제어할 수 있다고 가정하지 마.

한글 깨짐·오탈자·잘림과 모바일에서의 가독성을 최종 파일과 실제 화면에서 확인해줘.

#### 4.4 웹용 용량 최적화와 저장

제작 원본을 그대로 업로드하지 말고 최종 크기로 리사이즈·압축해줘. 외부 공유 호환성을 고려해 JPEG 등 적절한 형식을 선택하고, 최종 파일은 150~250KB를 목표로 최적화해줘. 글자나 사진이 흐려지면 용량을 억지로 맞추지 말고 품질을 우선해줘.

기존 이미지 저장소와 캐시 설정을 활용하고, 방문할 때마다 이미지를 생성하거나 외부 API를 반복 호출하지 마. 저장된 한 이미지 주소를 모든 용도에서 재사용해줘.

#### 4.5 제작 상태 저장과 재실행

장소·연결 글을 기준으로 대표 이미지 주소, 대체 설명(alt), 제작 상태를 저장해줘. 원본 사진의 출처 URL·장소 식별 정보·권리 확인 근거와 확인일·필수 출처 표시, 썸네일 문구, 파일 형식·크기·용량, 제작·업로드·검수 일시도 함께 관리해줘.

권리 확인 대기, 제작 대기, 제작 완료, 업로드 완료, 연결 완료, 검수 완료, 실패·보류를 구분하거나 동등한 단계별 상태를 관리해줘. 실패·보류 이유와 재시도에 필요한 사항을 저장하고, 파일이 생성됐다는 이유만으로 전체 완료로 처리하지 마.

같은 장소의 다른 시간권·패키지가 추가되거나 작업을 재실행해도 기존에 검수 완료한 썸네일을 재사용해줘. 원본·문구·디자인 변경 등 재제작이 필요한 경우만 새로 제작하고, 장소 식별자와 제작 입력 버전 또는 해시 등으로 불필요한 중복 생성을 방지해줘.

#### 4.6 예약 발행 전 완료 조건과 실화면 검증

예약 발행 대상으로 확정하기 전에 썸네일 제작·최적화·업로드·대표 이미지와 목록 카드 및 OG 이미지 연결·검수까지 완료해줘. 이 조건을 충족하지 못한 글은 보류하고, 하루 수량을 채우려고 미완성 글을 예약하거나 발행하지 마. 기존 하루 전국 합계 20개 발행과 마지막 날 잔여 수량만 발행하는 원칙은 유지해줘.

실제 모바일·PC 화면에서 이미지 비율, 잘림 여부, 한글 가독성, 출처 표시를 검증해줘. 공개 접근 가능한 이미지 URL의 응답과 형식·크기, 글의 공유 메타데이터와 대표 이미지·카드·OG가 같은 저장 주소를 사용하는지도 확인해줘. 미래 예약 글을 검증하려고 공개 목록·검색·사이트맵에 노출하지 마.

카카오톡 등 실제 공유 미리보기를 확인할 수 있으면 검증하고, 메타데이터 확인만으로 모든 외부 플랫폼의 실제 표시까지 검증했다고 보고하지 마.

이미지 생성·편집 기능을 사용할 수 없으면 제작 완료라고 처리하지 마. 실제 도구·계정·키·권한과 기존 저장소 연결을 확인한 뒤, 부족한 연결 사항을 구체적으로 기록하고 사용자 입력이 필요한 항목만 [내가채움]으로 표시해줘. 제작·업로드·화면 검증·공유 검증은 실제 완료 여부를 각각 보고해줘.

이 이미지 조건 외의 글 작성, 제휴링크 원문 보존, 내부링크, 제외·통합 규칙, 사이트 구성, 매일 20개 예약 발행 조건은 기존 요청을 그대로 유지해줘.

### 8. 제휴 고지와 사이트 구성

와그 공식 파트너스 안내에서 현재 지정된 제휴 고지 문구를 직접 확인해 각 글 최상단에 적용해줘. 지정 문구가 확인되지 않으면 다음과 같이 관계가 분명한 문구를 사용하고 공식 지정 문구라고 표현하지 마.

“이 글에는 와그 제휴 링크가 포함되어 있으며, 해당 링크를 통해 구매하면 일정액의 수수료를 제공받습니다.”

읽을 수 있는 크기와 대비로 본문·구매 버튼보다 위에 표시해줘.

메인 화면 ‘가을나들이’ 바로 오른쪽에 ‘입장권·체험’ 버튼을 추가하고, 발행된 장소 글을 지역과 테마별로 탐색할 수 있게 해줘. 기존 메뉴 디자인에 맞추고 모바일에서도 자연스럽게 배치해줘.

최근 추가한 기존 여행 제휴광고의 링크·배너·구매 버튼은 제거하고 와그로 교체해줘. 쿠팡 광고는 유지해줘.

기존 정보 글과 URL은 보존하고, 공식 관광정보 링크나 내부링크까지 광고로 판단해 삭제하지 마. 대응되는 와그 상품이 없는 광고 위치는 광고 요소만 제거해줘.

각 글에서 기존에 발행된 관련 지역·나들이·맛집·여행코스 글을 찾아 자연스럽게 내부링크로 연결해줘. 관련 없는 글을 억지로 연결하거나 존재하지 않는 주소를 만들지 마.

### 9. 매일 총 20개 예약 발행

한국시간 Asia/Seoul 기준으로 전체 지역 합계 하루 20개의 새 장소 글을 발행하도록 해줘.

우선 경기도부터 시작하고, 내가 서울·인천·다른 지역 링크를 추가하면 미발행 대기열에 합쳐 매일 여러 지역을 균형 있게 섞어줘. 지역별로 각각 20개가 아니라 전국 합계 20개다.

같은 지역이 계속 밀리지 않도록 대기 기간을 반영하고, 같은 날 비슷한 장소만 몰리지 않도록 판단해줘.

현재 링크는 조사·이미지 확보·작성·검수 후 예약해줘. 중복 통합과 제외 후 실제 글이 100개보다 적으면 억지로 100개나 5일을 채우지 마. 마지막 날은 남은 수량만 발행하고 검증이 부족한 글은 보류해줘.

새 링크가 들어오면 상품·장소·지점 중복을 확인하고, 기존 글의 이용권 업데이트와 신규 글 작성을 구분해줘. 미래 예약분만 필요에 따라 재편성해줘.

장소 데이터와 조사 결과, 글쓰기 원칙, 발행 상태, 일정은 프로젝트에 저장해 다음 대화에서도 이어서 작업할 수 있게 해줘.

대화창이 닫혀도 실제로 작동하는 예약 작업을 연결하고, 중복 실행 방지·실패 재시도·발행 이력·중지 기능을 마련해줘. 미래 예약 글은 공개 목록·검색·사이트맵에 노출하지 마.

새 링크를 등록할 수 있는 관리 경로를 마련해줘. 대화에 파일을 올리는 것만으로 사이트가 자동 수신한다고 가정하지 마.

### 10. 검증 후 결과 보고

실제 구현 후 다음을 확인해줘.

* 장소와 연결 상품이 일치하는가?
* 구매 버튼이 일반 상품 URL이 아닌 내 제휴링크를 사용하는가?
* 중복·커밍순·실외 물놀이가 발행 대상에서 제외됐는가?
* 와그 사진과 공공이미지가 해당 장소에 맞고 이용조건을 충족하는가?
* 글이 반복적인 홍보문이 아니라 방문 결정에 도움이 되는가?
* 제휴 고지·내부링크·모바일 화면·예약 발행이 정상인가?
* 기존 URL과 쿠팡 광고가 유지되는가?

방문할 때마다 글을 생성하거나 외부 API를 반복 호출하지 않도록 기존 캐시·정적화 구조를 활용해줘.

마지막에는 참고한 글쓰기 자료 URL, 실제 제외·통합 건수, 완성 글 수, 예약 일정, 구현 결과와 남은 설정만 간단히 보고해줘. 실제 예약 작업이 연결되지 않았다면 자동 발행 완료라고 보고하지 마.

## 2026-09-10 최종 이미지 조건 (앞선 상충 조건보다 우선)

- 제공된 사용 허용 사진을 본문에 우선 활용한다. 와그 사진에서 식별 가능한 얼굴을 임의로 사용하지 않는다. 사람이 없는 시설·풍경을 먼저 고르고, 얼굴이 있으면 편집 허락이 확인된 경우에만 얼굴이 나오지 않게 자른다. 편집 권한이 불명확하거나 얼굴 제외가 어렵다면 다른 사진을 선택한다. 본문과 대표 이미지 모두 동일하다.
- 사용할 사진 또는 편집 권한이 없으면 내장 imagegen으로 썸네일을 새로 만든다. 사진처럼 자연스러운 이미지와 일러스트 중 장소·본문에 맞는 방식을 자체 판단한다. 실제로 없는 시설이나 풍경을 해당 장소의 실제 사진처럼 만들지 않는다. 사진형 생성은 동물·소품 등 확인된 주제를 중심으로 하고, 시설 설명은 필요시 명백한 일러스트로 표현한다.
- 본문 AI 이미지도 꼭 필요한 경우에만 허용한다. 제공 사진으로 충분하면 추가 생성하지 않는다. AI 이미지에는 실제 촬영 사진이 아니라는 표시를 하고 사용하지 않은 공공사진 출처를 쓰지 않는다.
- 공공사진을 사용하거나 편집했다면 필요한 원본 출처를 유지하고, 이미지 안의 출처는 여백을 둔 오른쪽 하단에 작고 읽기 쉽게 배치한다.
- 장소당 대표 썸네일 한 장, 짧고 자연스러운 한글 방문 관심 문구, 1200×630 JPEG 품질 우선 최적화, 한 주소의 대표·목록·OG 재사용, 모바일·PC 비율 유지, 생성 이력과 검수 상태 저장 조건을 유지한다.
- 30개를 준비하되 한국시간 하루 총 20개(당일 발행분 포함)만 발행하며 나머지는 다음 날부터 예약한다. 기존 다른 종류의 글 작성 작업과 기존 URL·와그 제휴링크는 유지한다.

### 이용권 연결 영역 (2026-09-10 수정)
- 제목은 `[장소명] 이용권 알아보기`, 설명은 `방문 날짜에 맞는 이용권과 가격을 와그에서 확인해 보세요.`로 통일한다.
- 글의 `placeName`은 지점을 포함한 실제 장소명이다. 상품별 `catalog.products[].optionLabel`에는 확인한 이용권 종류만 저장한다. 장소명·광고 표현·`보기`는 넣지 않는다. 기존 affiliateUrl은 그대로 보존한다.
- 신규 글 검수 시 상품명과 포함 사항을 대조해 시간권·어린이권·왕복권·통합권·패키지를 구별하고 `optionLabelReview`에 출처와 확인일을 기록한다. 확인하지 못한 조건을 버튼 이름에 넣지 않는다.
- 버튼은 `[이용권 종류] 보기 ↗`, 아래 안내는 `이용 가능 시간과 포함 내역, 취소·환불 조건은 상품마다 달라요.`로 표시한다.
- 모바일은 단어 단위 줄바꿈, `보기 ↗` 묶음 유지, 최소 높이 44px와 버튼 간격 8px를 사용한다. 긴 패키지명은 자연스럽게 두 줄까지 허용하되 가로 넘침과 화살표 단독 줄바꿈을 확인한다.
