## 2026-09-12 추가 우선 규칙: 빈 비교 셀과 월별 텍스트 만료

- 비교표의 label과 includes는 실제 확인된 비어 있지 않은 문자열이어야 합니다. entryTime, duration, conditions는 문자열 타입을 유지하되 모르면 빈 문자열로 저장합니다. '별도 이용 제한시간 미확인' 같은 대체 문구를 반복 생성하지 않습니다. checkedAt과 sourceUrls의 실제 근거 검사는 유지합니다. 이전의 모든 셀을 채우라는 지시보다 이 규칙이 우선합니다.
- 모든 행의 duration이 빈 문자열이면 UI에서 이용시간 열을 생략합니다. 알 수 없는 이용시간을 운영시간이나 체류시간 추정으로 대신 채우지 않습니다. 단일상품 비교표 생략 규칙도 유지합니다.
- 월별 판매기간·일정은 제목과 intro에 넣지 않습니다. 기간 한정 정보는 실제 유효일 validUntil 메타가 있는 section 또는 ticketComparison에 모읍니다. 같은 내용을 본문과 FAQ에 반복하지 않습니다.
- sections[]와 faq[]는 선택 필드 validUntil: 'YYYY-MM-DD'를 지원합니다. 월별 일정이나 기간 한정 질문·답변에만 실제 확인된 유효일을 저장하고 상시 내용에서는 필드를 생략합니다. 날짜를 모르면 추정하지 않습니다. 판매 마감·운영일·티켓 발송·사용 기한의 의미는 구분합니다.
- sections/faq의 validUntil은 한국시간 해당 일 끝까지 유효합니다. 만료되면 해당 텍스트만 숨기며 section의 photoIndex, 기존 이미지·순서·배치·URL을 그대로 유지합니다. 만료된 텍스트가 있다는 이유로 기존 이미지나 글 전체를 삭제하지 않습니다. 상시 설명과 기간 한정 설명은 서로 다른 section으로 구성합니다. UI 시간 판정은 부모가 전달하는 renderedAt을 사용하며 신규 실시간 API를 호출하지 않습니다.
- 템플릿의 _optionalFields는 생성기 참고용 선택 필드 설명이며 공개 글 필드가 아닙니다. 실제 작성 결과의 sections/faq에는 필요한 validUntil만 넣습니다. 공개 투영은 sections와 faq의 기존 전체 필드를 보존합니다.

# 입장권·체험 공통 작성 지침

2026-09-12 최신 사용자 요구입니다. 기존 35개 글의 내용 개선 및 앞으로 작성할 글에 적용하며, 과거의 고정 분량·12개 항목·이미지 교체 지시보다 우선합니다.

## 내용과 말투

실제 장소와 지점을 먼저 소개하고, 그곳에서 어떤 경험을 할 수 있는지 구체적인 확인 정보로 설명합니다. 자연스러운 존댓말을 쓰며 방문한 척하는 후기, 상품명만 바꾼 반복 글, 과장, 검색어 반복을 쓰지 않습니다. 제목은 실제 장소와 본문에서 답하는 구체적인 방문 도움을 담습니다. 지역명 삽입을 강제하지 않습니다.

장소 소개 → 경험과 방문 준비 → 실제 이용권 비교 → 예약 안내 → FAQ를 장소에 맞게 구성합니다. 고정 섹션 수, 최소 글자수, 항목별 분량 할당은 없습니다. 설명이 필요한 정보를 충분히 쓰되 같은 내용을 표·본문·FAQ에 반복하지 않습니다. FAQ는 실제 질문과 근거 있는 답변으로 작성하며 '상품 페이지에서 확인하세요'만 답으로 쓰지 않습니다. 가격·운영시간·연령·키·주차·시설은 출처로 확인된 것만 씁니다.

`visitInfo`는 선택 필드입니다. 확인된 핵심 항목만 `{topic,status:"confirmed",value,sourceUrls,checkedAt}`으로 저장하고 sourceUrls는 실제 URL 문자열 배열입니다. 추천 대상·즐길 거리·소요시간·교통·주차 등을 모두 생성할 의무가 없습니다. 미확인·빈 항목은 생략하며 추측이나 unknown으로 12칸을 채우지 않습니다.

`ticketComparison`은 실제 옵션별 `[{label,entryTime,duration,includes,conditions,href?,sourceUrls,checkedAt,validUntil?}]`입니다. sourceUrls만 URL 문자열 배열이며 나머지는 문자열입니다. 입장 시점(entryTime), 이용시간(duration), 포함 내역(includes), 제한·예약·취소 조건(conditions)을 구별합니다. 단일상품은 ticketComparison을 생략하거나 빈 배열로 둘 수 있습니다. productIds.length > 1인 다중상품 글은 비어 있지 않은 비교표가 필수입니다. 단일상품 안에 일반권·오후권·야간권·패키지 등 variants가 있는지는 실제 상품 자료를 작성 검수에서 확인하고, 확인된 옵션 차이가 있으면 표로 안내합니다. 비교 행을 작성한 경우 모든 필수 필드와 출처 검사는 유지합니다. 단일권의 미확인 duration 등을 채우려고 표를 만들지 않습니다. 필수 비교표의 근거가 부족하면 초안과 보류 이유를 남깁니다. href는 제공된 해당 상품의 기존 affiliateUrl 원문만 쓰고 일반 상세 URL을 구매 링크로 쓰지 않습니다. sourceUrls는 글 sources에 등록된 실제 상품·공식 근거와 일치해야 합니다.

확인일은 실제 자료를 확인한 날짜이며 판매기간·운영일·티켓발송·사용가능일과 구분합니다. 월별 종료일을 본문에 반복하지 말고 비교 행 validUntil에 실제 확인된 유효일로 기록합니다. 사용에 필수적인 날짜는 그 의미를 밝혀 안내하며 판매 마감을 사용 기한으로 바꾸지 않습니다. 기한을 모르면 validUntil을 생략합니다. 서버의 기존 예약 작업에서 만료 7일 이내는 due, 만료 후 또는 확인일 7일 초과·잘못된 날짜는 stale입니다. 날짜만 있는 종료일은 한국시간 당일 끝까지 유효합니다. stale 옵션은 현재 유효하다고 안내하지 않고 재확인 필요 표시 및 신규 발행 보류 대상으로 다룹니다. 자동으로 새 확인일을 찍지 않습니다. 새 live API를 만들지 않습니다.

## 버전과 검수

개선한 기존 글과 신규 글은 `editorialRevision:"2026-09-12"`를 저장합니다. 신규 글의 `contentPolicyVersion:"tickets-2026-09-11"`은 그대로 유지합니다. 기존 30개 legacy에는 contentPolicyVersion을 추가하지 않고 기존 렌더러를 유지합니다. 개정 표시만으로 렌더러나 이미지 투영 방식을 바꾸지 않습니다.

## 이미지 보존과 제휴

이번 내용 개선에서는 기존 이미지 URL·순서·배치·크기·출처·썸네일 및 대표/목록/OG 연결을 그대로 유지합니다. AI 생성이라는 이유로 교체하지 않습니다. 앞으로도 같은 장소의 기존 검수 이미지를 먼저 재사용합니다. 사진 수 채우기나 무조건 썸네일 생성 지시는 폐기합니다. 신규로 필요한 이미지만 실제 장소·사용 허가·편집 권리·상업적 이용·얼굴 여부를 확인합니다. 권리 문제가 있으면 보류합니다.
